# Images and editorial sections across Coinscribed (v1)

Turns the sample-data news site into something that reads like a staffed publication: every article card, featured hero, lead story, and article page now carries a real (deterministic picsum) image, authors get avatars, and the homepage gains three editorial bands (Most Read, Explore by Topic, Editor's Picks). The three news pages that were still on the old rounded-pill design are rebuilt on the Ink & Oxblood utilities, and a new About page plus an enriched Footer round out the site. The picsum host is whitelisted in `next.config.js`, the `ArticleCard`/`Article`/`Author` types gain optional `imageUrl`/`readingTime`, and every image path has a `.thumb-duotone`/grey-circle fallback for when a URL is absent.

Watch for: the homepage fetches 12 articles but only renders 11 — the 12th is silently dropped by the slicing (confirmed, cosmetic). Reading time is a hard-coded `5` on all 24 entries rather than the "realistic 3-7 based on body length" the spec asked for (confirmed, cosmetic). The article-detail meta line emits a leading separator dot that would render orphaned if an author were ever missing (confirmed, latent — no sample article triggers it). No design-language or accessibility regressions found; `rounded-full` stays on avatars only, no emoji/`rounded-lg`/shadows introduced, dark-mode classes present on every new block, and lint + build are green.

**Verdict**: APPROVED

## High-level view

The image foundation is the load-bearing change: all image rendering is guarded by `imageUrl ?` with a graphic fallback, so a missing URL degrades to the old duotone plate rather than throwing. `next/image` needs the host whitelisted, and `picsum.photos` is correctly added to `remotePatterns` — without it every image would fail at request time. Content images carry the article title as alt text; decorative avatars fall back to an `aria-hidden` grey circle.

The homepage slicing is the one place worth a second look. With 12 fetched articles the sections carve up as featured[0] / sidebar[1–4] / grid[5–7] / editorsPicks[8–10], with Most Read deliberately re-showing the top five. That leaves index 11 fetched-but-unrendered — nothing breaks, but the fetch is wasted.

The three rebuilt news pages drop the `rounded-full`/`bg-zinc` pill tabs for eyebrow text links with an oxblood active state, and each gains a lead story plus a `rule-grid` of image cards. The active-tab semantics differ between them: on `/news` the active "All" is a non-interactive `<span aria-current="page">`, while the category page keeps every tab a real `<Link>` and marks the active one with `aria-current`. Both convey state to assistive tech; the inconsistency in focusability is the thing to note.

Reading time is a uniform `5` across all 24 entries — a data-quality miss against the intended 3–7 range, not a functional one. The About page and Footer carry no concerns.

<summary>Issues (5)</summary>

1. **Homepage drops the 12th article** — `getLatestArticles(12)` fetches 12 but the slices cover only indices 0–10; index 11 is never rendered. Either fetch 11 or extend a section (e.g. `editorsPicks = slice(8, 12)`) so the fetch isn't wasted.
2. **Uniform reading time** — all 24 entries hard-code `readingTime: 5` instead of the intended realistic 3–7 range keyed to body length. Vary the values so the byline reads as real editorial metadata.
3. **Orphaned separator dot in article meta** — the `&middot;` before the date in `app/news/[slug]/page.tsx` sits outside the `article.author &&` guard, so a missing author would render a leading dot. Move it inside the author block to match the listing pages.
4. **Inconsistent active-tab semantics** — `/news` renders the active "All" as a static `<span aria-current="page">` while the category page uses a focusable `<Link aria-current>`. Pick one pattern for both so keyboard/screen-reader behavior is uniform.
5. **Author avatar alt text** — meta and bio avatars use `alt={article.author.name}`, duplicating the adjacent visible name and adding noise for screen readers. An empty `alt=""` (decorative) would be cleaner since the name is already text.

### Homepage slicing leaves one article on the floor

```
articles = getLatestArticles(12)   // 12 items
featured      = [0]
sidebar       = [1,5)   -> 1,2,3,4
grid          = [5,8)   -> 5,6,7
trending      = [0,5)   -> re-shows 0..4 (intentional per spec)
editorsPicks  = [8,11)  -> 8,9,10
                           11 is never used
```

No section is starved and nothing is confusingly duplicated — Most Read openly re-ranks the freshest five, which is expected for a "most read" rail. The wrinkle is that index 11 is fetched and discarded. Bumping `editorsPicks` to `slice(8, 12)` (four picks) or fetching 11 removes the dead fetch.

### News pages rebuilt, with a tab-semantics split

Both `/news` and the category page shed the old `mx-auto max-w-7xl` + `rounded-full`/`bg-zinc-900` pill tabs for `container-page section-padding` and eyebrow text-link tabs, and both grow a two-column lead story above a `rule-grid` of `ArticleCard`s. The active-tab treatment diverges: on `/news` the active "All" is a non-focusable `<span aria-current="page">`, whereas the category page renders every tab — including the active one — as a `<Link>` with `aria-current` set conditionally. A keyboard user tabbing the `/news` nav will skip "All" while on the category page it's focusable. Aligning them — either make "All" a self-linking `<Link href="/news">` on `/news`, or drop it from the tab order on both — is the tidy fix.

### Article detail meta assembles a dangling separator

The date's leading `&middot;` lives outside the `article.author &&` conditional:

```tsx
{article.author && ( ... name ... )}
<span aria-hidden="true">&middot;</span>
<time dateTime={article.publishedAt}>...</time>
```

Every sample article has an author, so this never renders wrong today, but if an author were ever absent the row would open with a stray dot. The listing and Most Read rows guard their separators inside the author block, so this is an inconsistency as much as a latent bug.

### Design-language and accessibility conformance

Scoped to source files (excluding the task JSON), the diff introduces no `rounded-lg`, no `shadow-*`, and no emoji. `rounded-full` appears only on the four avatar elements — the sanctioned exception. The Footer's `rounded-full bg-oxblood` accent bar flagged in the FEAT-003 notes is pre-existing on `origin/main`, not introduced here. Topic-tile icons and eyebrows are colored via `getCategoryTone`, whose palette is the desaturated `category-*` tokens (aubergine/olive/steel/sepia), not teal/amber/bright signal colors. Every new block carries `dark:` variants across the homepage rails, rebuilt news pages, and About.

The avatars are the one accessibility soft spot: they use `alt={article.author.name}` while the author's name sits as visible text immediately beside them, so a screen reader announces the name twice. Treating avatars as decorative (`alt=""`) would be cleaner.
