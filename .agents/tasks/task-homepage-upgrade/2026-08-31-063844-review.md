# News-first homepage rebuild with live crypto ticker (v1)

The homepage was reordered into a news-first layout and seeded with competitor-inspired sections: a live CoinGecko crypto ticker at the very top, a slim hero band wrapping a featured article + headlines sidebar, a static market-data strip, the Latest News grid, trust-signal stats, the (now relocated) calculator highlights, the bank routing preview, and a UI-only newsletter signup. The section order matches the spec exactly and News now precedes Calculators. New client components handle the only interactive pieces (ticker fetch, newsletter form); everything else stays server-rendered. `npm run build` and `npm run lint` both pass, and there is no automated test suite to run.

Watch for: the CryptoTicker's live fetch hits CoinGecko's unauthenticated public endpoint every 60s per open tab with no backoff on rate-limit responses (likely); the marquee animation has no `prefers-reduced-motion` guard (confirmed); the ticker's up/down threshold treats an exactly-zero change as "up/green" (confirmed, cosmetic). None of these block shipping.

**Verdict**: APPROVED

## High-level view

The reorder is a straight reassembly of `app/page.tsx` into the required top-to-bottom order, with the calculator highlights and bank sections moved below the news content and the old inline article-card markup replaced by the shared `ArticleCard`. Slices (`articles[0]`, `slice(1,5)`, `slice(5)`) are all guarded — the featured slot falls back to a placeholder card and the grid only renders when non-empty — so a thin article set can't crash the page.

The only live data path is the CryptoTicker, and it's built to fail safe: server render and first client render share the same static fallback array (no hydration mismatch), and any fetch error, non-ok response, or partial payload leaves the last-good/fallback values in place. The tradeoff is that it polls CoinGecko's keyless public API every 60s from each client with no rate-limit awareness beyond bailing on a non-200.

The market-data widget is intentionally static and labels itself as illustrative. The newsletter form is UI-only by design — the email is never transmitted anywhere, which the code documents. Thumbnails across `ArticleCard` and the featured hero now always render a category-colored gradient placeholder keyed to the existing `CategoryBadge` palette, since sample articles carry no images; the `ArticleCard` change is backward compatible with its other four callers.

No security-sensitive surface is introduced: the newsletter collects but discards an email client-side, and the ticker only performs an unauthenticated GET to a third party.

### News-first reassembly and guarded slices

`app/page.tsx` fetches `getLatestArticles(8)` and splits into `featured = articles[0]`, `sidebarArticles = slice(1,5)`, `gridArticles = slice(5)`. Every consumer is guarded: the featured slot renders a placeholder card when `featured` is falsy, the Latest News section is wrapped in `gridArticles.length > 0`, and the sidebar `.map` renders nothing on an empty slice — so a short or empty article set degrades instead of throwing.

The section order is the spec order — CryptoTicker → hero + FeaturedArticle → MarketDataWidget → Latest News → TrustSignals → Calculators → Bank Routing → NewsletterSignup — with News before Calculators. The calculator array and bank markup were relocated intact, the amber-light/30 tint on the calculators band is preserved, and sections keep the `container-page`/`section-padding` rhythm and `border-brand-border-gray` dividers with dark-mode variants.

### CryptoTicker fetch lifecycle and fallback

```
SSR render ─┐
            ├─ FALLBACK_COINS (identical) ── no hydration mismatch
client render ─┘
                 │
useEffect ──► fetchPrices() ──► fetch(CoinGecko, no-store)
                 │                   │
              setInterval 60s        ├─ !res.ok ──► return (keep prior state)
                 │                   ├─ per-coin: use usd/usd_24h_change only
                 └─ cleanup:         │   if typeof === number, else fallback
                    active=false     └─ catch ──► keep prior state
                    clearInterval
```

State is seeded with `FALLBACK_COINS` so server and first client render match, and each coin independently falls back to its static value when a field is missing or non-numeric, so a partial payload can't surface `NaN`/`undefined`. The `active` flag plus `clearInterval` cleanup close off a post-unmount state update and a leaked interval.

The fetch targets CoinGecko's unauthenticated public endpoint on a 60s interval per open tab; a rate-limit (429) is handled identically to any other non-ok (keep last-good data) with no backoff, so a heavily-trafficked page keeps hitting the endpoint every minute (likely, low impact given the fallback). `up = coin.change24h >= 0` paints an exactly-zero change as green with an up-arrow (confirmed, cosmetic).

The marquee is a CSS animation (`animate-marquee`, 30s linear infinite) with the coin list duplicated so the `-50%` translate loops; hover pauses it. There is no `prefers-reduced-motion` guard (confirmed) — a continuously scrolling bar is exactly the motion that guard exists for, and `motion-reduce:animate-none` is a one-class fix. The duplicated list also means assistive tech may encounter each price twice; consider `aria-hidden` on the duplicate set (possible).

### Static market data and UI-only newsletter

MarketDataWidget is deliberately static (real-time index data needs a paid key) and renders an "Illustrative values shown for demonstration. Not live market data." disclaimer, so it won't be mistaken for live quotes.

NewsletterSignup validates a non-empty email, flips to a "Thanks! You are subscribed." status, and clears the field. The email is never transmitted anywhere — documented as a deliberate placeholder for a future Mailchimp/Resend integration — which matches the UI-only spec and leaves no credential/PII-transmission surface. The heading copy matches the spec string.

### Category-gradient thumbnails and ArticleCard compatibility

`lib/category-styles.ts` adds `getCategoryGradient(slug)` returning Tailwind gradient classes keyed to the same crypto/economy/markets/banking scheme as `CategoryBadge`, defaulting to teal for unknown/undefined slugs. `ArticleCard` now always renders a gradient placeholder wrapped in the article link (previously a plain gray block only when `mainImage` existed, nothing otherwise). This is backward compatible with the four other `ArticleCard` callers (`/news`, `/news/[slug]` related, category pages), which gain the placeholder automatically; the featured hero uses the same helper. All gradient tokens (`teal-medium`, `teal-primary`, `amber-badge`, `amber-accent`, plus stock `violet/emerald/orange`) resolve in the Tailwind config.

One inconsistency: the `ArticleCard` type declares `category` as required, but `ArticleCard.tsx` and `FeaturedArticle.tsx` read it with optional chaining (`article.category?.slug.current`). Harmless since the gradient helper handles `undefined`, but the type contract and the runtime guards disagree.
